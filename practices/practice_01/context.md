## Context Pack для первого рабочего сценария

### Факты и правила

- POST /api/reviews принимает тело запроса как словарь и обращается к полю payload["diff"]. Источник: app/api.py:35-37 в TRAINING_PR.diff.
- ReviewService.review(diff: str) формирует строковый промпт: "Review this pull request and find problems:\n{diff}", вызывает llm.generate(prompt) и возвращает {"comment": answer}. Источник: app/review_service.py:19-22.
- Протокол LLM определяет метод generate(self, prompt: str) -> str. Источник: app/review_service.py:9-13.

### Формат входа и результата

- Вход API: JSON-объект с ключом "diff" (строка с содержимым диффа PR).
- Результат API: JSON-объект вида {"comment": "строка — ответ LLM"}.

### Ограничения и запрещённые действия

- Ключ "diff" обязателен; при его отсутствии текущая реализация вызовет KeyError и приведёт к 500 (необработанная ошибка). Источник: прямой доступ payload["diff"] в app/api.py:37.
- Ответ фиксирован как {"comment": str}; иные поля не формируются текущей реализацией. Источник: app/review_service.py:21-22.

### Хороший пример

Запрос:

```
POST /api/reviews
Content-Type: application/json

{"diff": "diff --git a/x b/x\n..."}
```

Ответ:

```
200 OK
{"comment": "<текст обнаруженных проблем>"}
```

### Плохой пример

Запрос без обязательного поля:

```
POST /api/reviews
Content-Type: application/json

{}
```

Ожидаемая проблема: KeyError на payload["diff"], что приведёт к 500 вместо валидационной ошибки 4xx. Источник: app/api.py:37.

### Что пока неизвестно

- Требования к аутентификации/авторизации.
- Ограничения на размер входного диффа и обработку больших тел запросов.
- Требования к структуре ответа LLM (формат комментария).
- Реализация и конфигурация app.dependencies.review_service.

- Тип промпта: zero-shot для первичного прохода, затем master prompt.
