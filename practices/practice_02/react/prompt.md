# ReAct: задание для агента по улучшению артефакта Unit-проверок

Роль:
Ты — ReAct-агент по качеству документации. Твоя задача — критически проанализировать артефакт unit‑проверок и подготовить его улучшенную версию в том же формате, опираясь исключительно на разрешённый контекст.

Исходные материалы (целевой артефакт и разрешённые источники фактов):
- Target (что улучшаем): practices/practice_01/tests_unit.md
- Разрешённые источники фактов (только они):
  - practices/practice_01/TRAINING_PR.diff
  - practices/practice_01/context.md
  - practices/practice_01/problem.md

Что сделать:
1) Проанализировать practices/practice_01/tests_unit.md на полноту, точность и воспроизводимость. Выявить слабые места: неполные или двусмысленные формулировки, недостаточная конкретика Evidence (без диапазонов строк), пропуски в покрытии (например: отсутствие/неточность проверки точного префикса промпта, количества вызовов LLM, поведения при пустом `diff`, негативный сценарий отсутствующего ключа `diff` в `create_review`).
2) Сформировать исправленный артефакт строго того же формата и структуры и сохранить результат по пути: practices/practice_02/react/tests_unit_v2.md.
   - Заголовок: `# Unit-проверки`.
   - Таблица с колонками ровно в таком порядке: `Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Evidence`.
   - В Evidence указывать точные ссылки на разрешённые источники с указанием файла и диапазонов строк (например: `TRAINING_PR.diff: app/review_service.py:19-22`, `context.md: 21-30`, `problem.md: 15-22`).
   - После таблицы добавить раздел `## Как использовали AI` с краткой фиксацией использованного промпта (ссылка на practices/practice_02/react/prompt.md) и что проверили вручную. Не добавлять новых разделов.
3) Обновить practices/practice_02/react/experiment.md:
   - В разделе `## Ответ со ссылками на источники` оставить Markdown‑ссылку на итоговый артефакт: `[tests_unit_v2.md](./tests_unit_v2.md)` и перечислить использованные выдержки из разрешённых источников с указанием строк.
   - Заполнить все оставшиеся пустые разделы этого файла по существующим заголовкам. Не добавлять своих новых разделов, заголовков или полей. Разделы «ReAct» и «Запрос» уже заданы — их структуру не менять.

Ограничения и стиль:
- Использовать ТОЛЬКО разрешённые источники фактов. Любое утверждение в таблице должно иметь подтверждение в Evidence.
- Сохранять исходный формат и порядок колонок, не добавлять новые колонки/разделы.
- Делать минимальные правки, достаточные для устранения слабостей.
- Язык: русский. ASCII, без экзотических символов.

Ключевые моменты, которые часто упускают (проверь и при необходимости добавь в таблицу):
- Точный префикс промпта: "Review this pull request and find problems:\n{diff}" и сам факт формирования строки с `diff`. Evidence: TRAINING_PR.diff по app/review_service.py.
- Ровно один вызов `llm.generate` с ожидаемым промптом; отсутствие лишних вызовов.
- Возврат структуры `{"comment": <строка>}` без лишних полей; тип значения — строка.
- Пустой `diff` не ломает контракт: вызов всё равно происходит, схема ответа неизменна.
- `create_review(payload: dict)` выбрасывает `KeyError` при отсутствии ключа `"diff"` (текущее состояние) — зафиксировать как негативный юнит‑кейс факта. Evidence: TRAINING_PR.diff по app/api.py.

ReAct-процедура (следовать циклу мысли‑действия‑наблюдения):
1) Мысль: кратко сформулируй текущую цель и проверяемые гипотезы. Укажи, каких фактов не хватает.
2) Действие: READ целевой файл и разрешённые источники; EXTRACT_FACTS с цитатами и строками; DIAGNOSE слабые места исходного артефакта; COMPOSE таблицу v2; WRITE результат в practices/practice_02/react/tests_unit_v2.md; UPDATE журнал practices/practice_02/react/experiment.md в существующих разделах; VALIDATE критерии приёмки.
3) Наблюдение: зафиксируй вывод каждого действия и проверку критериев. Если что-то не выполнено — опиши, что мешает.

Ограничения действий:
- Разрешено: читать только перечисленные файлы; формировать и записывать tests_unit_v2.md; редактировать только practices/practice_02/react/experiment.md в существующих разделах; ссылаться на источники с номерами строк.
- Запрещено: использовать иные источники; менять структуру артефакта и experiment.md (не добавлять новые разделы/поля); выдумывать факты без Evidence; изменять другие файлы.

Стоп‑условие и вопрос человеку:
- Остановись, когда выполнены критерии приёмки (см. ниже). Если критически не хватает подтверждений из разрешённых источников, задай вопрос: «В разрешённых источниках нет подтверждения <X>. Подтвердить или исключить этот пункт из таблицы?»
