# REPORT_01 — найденные уязвимости (до фиксов)

Ниже приведены подтверждённые проблемы в учебном сервисе Mini Shop. Для каждой — описание, шаги воспроизведения, воздействие и рекомендации.

## 1. IDOR в профилях (`GET /profile?id=`)
- Тип: Незащищённый прямой доступ к объекту (IDOR), SQL-инъекция по строковой подстановке.
- Шаги:
  1) `GET /profile?id=2` возвращает профиль другого пользователя.
  2) Код: `self.rows(f"SELECT * FROM profiles WHERE id = {query.get('id', '1')}")` — подстановка без параметров и без проверки владельца.
- Воздействие: раскрытие ПДн пользователей.
- Рекомендации: использовать параметризованные запросы и связывать id сессии с владельцем; сервер сам определяет владельца по `X-Token`.

Артефакт: evidence/before/profile_id_2.json

## 2. Незащищённый поиск (`GET /search?q=`)
- Тип: SQL-конкатенация без параметров; утечка данных через широкий поиск.
- Шаги: `GET /search?q=TEST_` возвращает всех пользователей. Код использует `LIKE '%{q}%'` через f-string.
- Воздействие: потенциальные SQL-инъекции/брутфорс данных.
- Рекомендации: параметризованные запросы; ограничение результатов и ролей.

## 3. Список заказов без аутентификации (`GET /orders`)
- Тип: Отсутствие контроля доступа.
- Шаги: `GET /orders` возвращает все заказы без токена.
- Воздействие: раскрытие бизнес-данных/истории покупок.
- Рекомендации: требовать сессию, фильтровать по владельцу.

Артефакт: evidence/before/orders_all.json

## 4. Подмена роли заголовком (`GET /admin/export`)
- Тип: Trust on first use заголовка `X-Role`.
- Шаги: `curl -H 'X-Role: staff' /admin/export` возвращает профили.
- Воздействие: эскалация привилегий, утечка профилей.
- Рекомендации: определять роль по серверной сессии (токен), игнорировать `X-Role` от клиента.

Артефакт: evidence/before/admin_export_as_header.json

## 5. Небезопасные файловые операции (`GET /files`, `POST /assistant/execute`)
- Тип: Отсутствие проверок полномочий внутри sandbox; IDOR внутри периметра.
- Шаги:
  - `GET /files?user=bob&path=receipt.txt` выдаёт чек другого пользователя.
  - `/assistant/execute` с `{'tool':'read_file','arguments':{'path':'private/operator-note.txt'}}` возвращает секрет оператора.
  - `/assistant/execute` с `{'tool':'delete_tree','arguments':{'path':'files/alice'}}` удаляет файлы клиента.
- Воздействие: чтение приватных файлов, уничтожение данных.
- Рекомендации: проверять владельца по сессии и роли; ограничить инструменты по ролям; валидировать пути в пределах каталога пользователя.

Артефакты: evidence/before/files_bob_receipt.json; интерактивная сессия показывает чтение `private/operator-note.txt` и удаление каталога клиента.

## 6. XSS/DOM-инъекция в обзорах (`GET /reviews/view`)
- Тип: Отсутствие экранирования HTML.
- Шаги: `POST /reviews` с `text` = `<img src=x onerror="fetch('/admin/export')">` — `/reviews/view` возвращает HTML с исполняемым атрибутом.
- Воздействие: выполнение JS в браузере оператора; возможность CSRF/кражи данных.
- Рекомендации: экранировать HTML (escape), рендерить в безопасном виде, использовать CSP.

Артефакт: evidence/before/reviews.html

## 7. Prompt Injection путь (планирование)
- Тип: Инструкции в отзывах попадают в `GET /assistant/context` и могут воздействовать на модель.
- Шаги: добавлен отзыв с инструкцией вызвать `export_profiles()`; контекст содержит инструменты и отзыв.
- Воздействие: модель может спланировать опасное действие; сервер также без проверок исполняет `export_profiles/delete_tree/read_file` по решению.
- Рекомендации: укрепить сервер — проверять полномочия инструмента по сессии, ограничить аргументы, логировать и блокировать опасные действия; обновить системные промпты и валидаторы.

## Общее
- Логи (`GET /debug/logs`) содержат заголовки и тела — может утекает приватный токен; следует фильтровать чувствительные поля.

## Вывод
Сервис намеренно уязвим: он доверяет входу пользователя для SQL/роль/файлы и инструменты помощника. Основной фокус фиксов — серверная авторизация по токену, параметризованные запросы, ограничения по владельцу, экранирование HTML и RBAC для инструментов ассистента.
